## 설계 방향

Wave는 시스템 소프트웨어에 필요한 제어를 소스 코드에서 숨기지 않는 방향을 지향합니다. 그 방향은 다음 기능으로 드러납니다.

- 변수, 함수 인자, 반환값과 복합 타입의 타입을 명시합니다.
- `ptr<T>`, `&`, `deref`로 주소와 메모리 접근을 코드에 드러냅니다.
- C ABI 경계를 `extern(c)`와 `export(c)`로 선언합니다.
- 네이티브 대상, CPU 기능, 링크 옵션과 프리스탠딩 빌드를 `wavec`에서 제어할 수 있습니다.
- 일반 프로그램 구성에는 함수, 구조체, 열거형, 제네릭과 `proto`를 사용합니다.

## 언어와 표준 라이브러리의 경계

Wave 컴파일러가 직접 이해하는 문법과 `std` 모듈에서 제공하는 기능은 구분됩니다. 예를 들어 `print`, `println`, `input`은 이 릴리스에서 파서가 직접 처리하는 문장이지만 문자열 검색, 파일 시스템, 네트워크, 메모리 도우미 등은 표준 라이브러리 모듈에 구현되어 있습니다.

이 구분을 알면 기능이 언어 문법인지 라이브러리 API인지, 또는 툴체인 기능인지 찾기 쉬워집니다.

## 명시적 변경 가능성

```wave
let fixed: i32 = 10;
let mut state: i32 = 0;
var counter: i32 = 0;
```

`let`은 재대입할 수 없고 `let mut`과 `var`는 재대입할 수 있습니다. 이 차이는 특정 분야에만 적용되는 스타일 규칙이 아니라 실제 코드 생성 단계에서 검사되는 언어 의미입니다.

## pre-beta에서의 문서 원칙

현재 컴파일러에는 lexer가 예약한 철자와 아직 완성되지 않은 구현 경로가 함께 존재합니다. 따라서 이 문서는 “토큰이 존재한다”는 이유만으로 기능을 지원한다고 설명하지 않습니다. 실제 파서와 코드 생성 경로가 동작하는 문법을 중심으로 설명하고, 알려진 제한은 해당 페이지에 따로 기록합니다.
